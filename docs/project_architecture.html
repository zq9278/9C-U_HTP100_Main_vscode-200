目录与程序架构分析

当前 v2 工程以单一应用任务为核心，将治疗状态、执行器切换和安全停机集中到 AppController，再通过 AppPort 调用板级实现。目标是避免旧工程中 多任务共享电机/SPI、强制删除任务和分散全局状态造成的竞态。

单应用所有者 10 ms 协作循环 非阻塞回零 屏幕拥有倒计时 充电禁止治疗

1. 总体结论

v2 已经从“多个业务任务直接操作硬件”转为“一个业务控制器串行决策”。总体方向正确， 电机/SPI 竞态风险显著降低；目前主要技术债已从并发失控转移到板级文件过大、恢复策略不对称和测试自动化不足。

1

业务任务

唯一的 freertos_main 高优先级任务运行全部治疗业务，避免多个任务争用 TMC5130、ADS1220 和状态变量。

10 ms

主循环节拍

串口、按键、眼盾、电源、状态机和 LED 都在同一循环内协作推进；具体控制周期由各模块自行限频。

85.7 KB

当前 Debug Flash

最近构建约占 65.4% Flash、20.9 KB RAM（56.9%），仍有扩展余量，但应继续关注任务栈和日志缓冲。

架构上最重要的改进 中断不再直接执行业务，应用任务不再被动态删除；所有停止原因统一经过“立即关闭危险输出 → 回零 → 决定空闲/故障/关机”的路径。

3. 分层架构

交互 / 事件
ScreenProtocol 屏幕命令、屏幕遥测、按键事件、PWR_SENSE、电池与眼盾采样。
业务编排
AppMain 单循环调度；AppController 保存唯一业务状态并决定何时启动、停止、回零、计数和报错。
抽象接口
AppPort 以函数表形式声明加热、电机、压力、眼盾、电源、灯光、存储和屏幕能力，使状态机可脱离 HAL 测试。
板级服务
BoardPort 只组装 AppPort；TreatmentHw 承担回零、温控和压力流程；各驱动分别封装 TMC5130、ADS1220、眼盾 I2C、充电、电量、WS2812、板载存储和屏幕 UART。
HAL / 硬件
STM32 HAL + Core 提供 GPIO、SPI、I2C、UART、TIM、DMA、EXTI 和启动代码。
依赖方向 AppController → AppPort ← BoardPort → TreatmentHw / Drivers → HAL。业务层不直接包含具体 GPIO 或总线句柄；板级层不应反向决定治疗业务状态。

4.2 Board_Init 顺序

  1. 拉高 SPI 片选、关闭 TMC5130 和加热输出。
  2. WS2812 数据保持低，关闭灯电源 300 ms，重新上电后先发送黑帧。
  3. 配置 BQ25895：固定 5 V 输入、2 A 输入限制、1.984 A 充电、4.208 V、64 mA 终止、关闭寄存器看门狗，并逐项回读。
  4. 初始化 BQ27441：容量 3300 mAh；仅在 ITPOR 或配置不匹配时重写参数；等待测量初始化完成后才使用 SOC。
  5. 初始化 ADS1220、写寄存器并 RREG 回读验证。
  6. 加载持久化计数，启动 USART2 Receive-to-Idle DMA。

5.1 开始条件

  • 状态必须处于 IDLE，模式有效且没有故障。
  • 外部充电输入不存在。
  • 回零有效；压力模式还要求 ADS1220 去皮有效。
  • 眼盾必须是新眼盾、当前会话已使用眼盾，或服务眼盾。
PREHEAT 的含义 当前状态机不会因为温度达到 40℃自动从 PREHEAT 跳转；正式开始仍由屏幕/按键的启动事件触发。这与“屏幕拥有流程和倒计时”的兼容策略一致，但协议双方必须保持一致。

6. 模块职责

AppMain

系统业务调度器。只做事件采集、周期轮询和调用，不保存复杂业务逻辑。

串口喂入按键100 ms 眼盾1 s 电源10 ms tick

AppController

唯一的治疗状态所有者，保存 AppSnapshot 与内部时序；决定模式切换、眼盾报废、计数、安全停机、回零和故障恢复。

状态机温度安全压力安全电量策略

ScreenProtocol

解析 13 字节工作帧与 11 字节设置帧，校验 CRC 和帧尾，将命令转换为 Controller API；负责预设和存储命令。

5A A56A A6CRC16FF FF

AppPort

业务层和硬件层之间的依赖倒置接口。测试用假实现替代真实 HAL；固件由 g_port 函数表绑定 BoardPort。

可替换可测试不暴露 HAL

BoardPort

作为薄适配层组装 AppPort，维护按钮/掉电事件，并把初始化、周期调用和 ISR 转发给独立模块。

约 140 行依赖组装接口稳定

TreatmentHw / Drivers

治疗硬件服务集中回零、PID 和压力阶段算法；芯片访问、I2C 恢复、DMA 缓冲和非易失存储由各自驱动维护，模块状态不再堆积于 BoardPort。

单一职责总线隔离行为等价

BQ27441 Gauge

独立维护电量计 Data Memory 配置，保护学习数据，检查 INITCOMP 后才允许 SOC 参与业务判断。

3300 mAhITPOR回读校验

AppLog / Hooks

USART1 输出带毫秒时间戳的文本日志；断言、栈溢出和 malloc 失败时保存最小现场并停机，避免在损坏栈上格式化日志。

115200阻塞发送GDB 可读现场

Core / HAL

完成时钟和外设初始化，中断回调只把数据或事件交给 BoardPort；FreeRTOS 只创建一个 2048 字节栈的高优先级业务线程。

CubeMXCMSIS-RTOS2STM32 HAL

8. 屏幕协议与倒计时

主板兼容现有两类帧，屏幕仍然拥有倒计时。主板保存治疗分钟数，但不会生成第二套倒计时；屏幕发送 0x8900 才被视为自然结束并计数。

工作帧

5A A5 开头，固定 13 字节，负载通常为 float/u32，末尾 CRC + FF FF。

主要输入：0x1041 加热准备、0x1005 压力准备、0x1037 自动准备、0x1040/0x1006/0x1036 开始、0x8900 自然结束。

设置帧

6A A6 开头，固定 11 字节，负载通常为 u16，处理预设选择、温度/压力/时间存储和擦除命令。

开机同步：0x1050 → 0x00AD 应答，同时发送软件版本、配置和预设。

故障码发送当前关闭 APP_ENABLE_SCREEN_FAULT_REPORT=0，因此 0x2070 故障帧被宏屏蔽；故障仍保留在本地状态和日志中。

9. 充电、电量与灯光

9.1 两颗芯片职责

BQ25895：充电过程真值

  • 检测外部 5 V：VBUS_GD 或 PG_STAT。
  • CHRG_STAT=3 才是真正 Charge Done。
  • 目标约 4.208 V，充电电流约 1.984 A，终止电流 64 mA。
  • Charge Done 仍视为“外部电源存在”，继续禁止治疗。

BQ27441：电量显示与低电量

  • 提供 SOC 百分比和电池电压。
  • SOC=100% 可能早于 BQ25895 Charge Done。
  • INITCOMP 前的临时 SOC=0 不参与判断。
  • SOC≤1% 提示；无外部电源且≤3150mV连续5次才关机。

9.2 LED 优先级

  1. 满电：外部电源存在且 CHRG_STAT=3，白色常亮。
  2. 充电：白色呼吸，6 秒周期，亮度 4～72，40 ms 更新。
  3. 故障/眼盾拔出提示：黄色 0.5 秒节拍，闪 3 次；不永久锁定灯光。
  4. 低电量：不充电时黄色闪烁。
  5. 普通状态：白色常亮。

充电和满电会取消正在等待的黄色闪烁；恒定颜色在 TIM16 DMA 忙时保留更新请求并在下一轮重试。

10. 安全策略

保护触发条件软件动作恢复
超温原始温度连续 5 s ≥ 44℃关加热/停电机、回零、故障当前代码在回零成功后自动清除
超压压力 ≥ 650 mmHg先停电机，再记录原始值并回零去皮有效且回零成功后自动清除
TMP112 通讯治疗中读取失败关闭危险输出、回零、故障眼盾重新确认且回零有效后清除
ADS1220 通讯DRDY/SPI 失败停止压力控制并进入故障当前未自动恢复
回零8 s 未检测参考位或持续 SPI 失败停电机、关闭驱动、MOTOR_HOME当前未自动恢复
眼盾拔出治疗中连续3次确认 absent安全停止、回零、黄灯3次不锁故障；需有效眼盾才能再开始
充电插入VBUS_GD/PG 有效中断治疗并回零，保持设备开启拔掉外部电源后可重新准备

11. 中断、并发与资源所有权

现在的规则

  • UART2 ISR：复制 DMA 数据到环形缓冲并重启接收。
  • 按键/PWR ISR：只设置布尔事件标志。
  • TIM16 DMA 完成：停止 DMA 并释放 WS2812 ready 标志。
  • 所有 TMC5130 SPI 操作只从应用任务路径调用。
  • 不删除、不挂起、不恢复业务任务。

为什么能避免旧故障

旧故障来自任务在 HAL_SPI_Transmit() 内被强制删除，HAL/SPI 状态无法清理。v2 回零是 home_begin + home_poll 非阻塞状态机，与压力控制共享同一个任务所有者，因此不存在异步删除 SPI 调用栈。

仍需注意 USART1 日志使用最长 30 ms 的阻塞发送；虽然只有一个业务任务，密集日志仍可能扰动 20 ms 压力控制节拍。高频路径应继续限频，后续可改为 DMA 日志队列。

13. 当前风险与整改建议

以下不是说当前代码不能运行，而是指出下一轮重构最值得优先处理的位置。

高
Board_Init 失败后永久停在循环BQ27441 或 ADS1220 一次启动失败就不再恢复，也没有看门狗重启。建议加入分级初始化、退避重试、故障灯和明确的降级状态。
高
I2C1 缺少与 I2C2 同等级的恢复眼盾总线已有 SCL 脉冲恢复和 HAL 重建；BQ25895/BQ27441 仍直接调用 HAL I2C。充电/电量总线卡死时可能长期失去电源判断。
低
驱动拆分后的接口仍以板级单例为主board_port.c 已由约 1300 行降至约 140 行，但硬件模块仍使用全局 HAL 句柄。若以后需要驱动级主机测试，可继续把 SPI/I2C 访问注入为总线接口。
中

建议的下一步重构顺序

  1. 先给 I2C1 加总线恢复、连续失败计数和安全降级，补齐电源链路可靠性。
  2. 把现有状态机测试接入 CMake/CTest，并为充电、眼盾拔插和故障恢复补测试。

  5. 最后将日志改为非阻塞 DMA，并评估 IWDG 与启动失败恢复策略。
