## 1 扳机按键消抖

0920版本直接将扳机下降沿作为按钮事件；本次加入非阻塞的软件消抖，防止一次按压被重复识别，造成治疗刚开始就立即停止。

- 按下稳定至少30 ms后，产生一次动作事件。
- 按下确认期间再次收到下降沿，会重新计算按下确认时间。
- 长按不重复触发。
- 释放稳定至少30 ms后，才允许下一次按下触发。
- 中断只记录下降沿提示，主循环结合实际引脚电平与时间完成确认。

## 2 低电压自动关机策略

| 状态 | 0920版本 | 当前代码 |
| --- | --- | --- |
| 正式治疗 RUNNING | 连续低压达到条件后中断治疗并安排关机 | 不因低电压采样请求自动关机，每次电源检查清除低压确认计数 |
| 停止或完成治疗后 | 按低压规则处理 | 重新累计低压确认，达到条件后回零并请求关机 |
| 预热 准备 空闲 | 按低压规则处理 | 保留原低压关机规则 |
| 低电量提示 | 根据SOC提示 | 保留 |
| 实际掉电输入 充电联锁 其他故障 | 按原流程处理 | 保留 |

低压条件仍为：无外接电源、电压不高于3150 mV、连续5次确认。电源轮询配置为100 ms，实际间隔受任务执行和器件通信耗时影响。

这里的“治疗中不关机”仅针对软件低电压采样引起的自动关机，不会阻止实际供电丢失、电池保护板关断或其他故障停止。预热不属于本次豁免的RUNNING状态。

相关文件：[app_controller.c](../App/Src/app_controller.c)。

## 3 统一TMP112读取与寄存器诊断

### 3.1 统一读取入口

新增`tmp112_read_register()`，温控、遥测和寄存器诊断共同经过该入口，再调用原有I²C2读取函数。

统一使用控制路径原有策略：两个数据字节、50 ms单次超时参数、最多两次尝试、重试前等待2 ms，以及原有总线恢复条件。相比此前独立诊断版，诊断不再使用不同的超时和重试策略。

### 3.2 逐次读取日志

每次TMP112实际读取均打印寄存器地址、尝试次数、HAL返回状态和I²C错误标志。

- 成功时打印收到的两个原始字节。
- 失败时打印`raw=INVALID`；它不代表零，也不代表FF。
- 总线恢复继续输出已有`[I2C2] Recovery`日志。

### 3.3 周期诊断与共享温度结果

主循环新增`EyeDriver_DiagnosticsTick()`，约每秒诊断一次：

| 地址 | 寄存器 |
| --- | --- |
| `0x00` | 温度 TEMP |
| `0x01` | 配置 CONFIG |
| `0x02` | 低温阈值 TLOW |
| `0x03` | 高温阈值 THIGH |

最近500 ms内有温控或遥测读取时，温度诊断引用同一次读取结果，包括失败状态；否则通过公共函数主动读取。日志带采样时间和数据年龄。其他三个寄存器依次读取，与温度不是同时采样。

诊断增加了I²C访问和串口输出，会影响主循环时序；当前仍带有台架测试用途的诊断行为。

相关文件：[eye_driver.c](../Bsp/Src/eye_driver.c)、[eye_driver.h](../Bsp/Inc/eye_driver.h)、[app_main.c](../App/Src/app_main.c)。

回退时间控制治疗循环中的回退阶段，不控制停止治疗后的回零时间。

- 源码版本号由`20260920`改为`20261024`，通过统一的`PRODUCT_VERSION_NUMBER`提供给屏幕与上位机。
